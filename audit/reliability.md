# Reliability audit — 2026-10-18

Scope: static inspection and 18 offline tests in `tests/test_controls.py`. No model execution, scaling, human labels, evaluation scores, or comparison files were accessed. All 18 tests passed (one ResourceWarning for an unclosed rates CSV).

## Findings

1. **P1 — Scale command silently selects the older classifier.** `pipeline/gate.py:4-16` imports bare `core` and `saved` and never loads a classifier profile. Their default is Gemma, whereas `pipeline/run.py` defaults to qwen-v3. Gate eligibility checks only a fixed file's `status`, and synthetic quality evidence is likewise not bound to the active fingerprint. A completed old Gemma gate can authorize a different configuration, and a current Qwen pilot will not be the model actually scaled. Reproduction requires no inference: inspect `python3 pipeline/gate.py --help` (no profile option) and default `core.CONFIG`. Fix: require an explicit profile, propagate a single module/config instance everywhere, and require prior-gate and quality manifests with the exact active fingerprint and input identity.

2. **P1 — Interrupted successful responses can be called again.** `pipeline/core.py:130-137` commits successful call metadata, returns its result, and only later `execute.save_batch` commits the label/cache (`164-176`). A crash or SIGINT between these commits leaves a successful response but no label. Resume checks labels/cache only and issues another request; saved request/response artifacts are never reconciled. The checkpoint manifest promises reconciliation, but does not implement it. The existing resume test covers already committed labels, not this crash window. Fix: persist a validated result and its label/cache in one transaction, or reconcile validated successful calls before requesting missing rows. Add a synthetic crash-after-success-before-label test. No paid adapter is enabled, so this currently wastes local runtime rather than money.

3. **P2 — Offline projection depends on an optional working database.** `cost/calculator.py:19-25` chooses the latest measurement by filename, then loads its call durations from `data/analysis10000.sqlite` or `data/checkpoint500.sqlite`. If that DB is absent, it falls back to pilot calls but filters them by the later run ID; all stage estimates become null. Thus a package containing cost/evidence but no working DB cannot reproduce the purported refreshed runtime. Selection also does not require `status=complete` or a matching classifier. Fix: publish immutable per-gate call summaries beside measurements, validate run/config identity and completion, and select a named benchmark explicitly.

4. **P2 — Elapsed-time projection omits per-request overhead.** `cost/calculator.py:31-38` extrapolates only `duration_seconds` recorded around the HTTP request/validation. It omits per-row SQL/cache lookup, JSON request writes, call/label commits, retry sleeps, and limiter waits, then adds a fixed 12 seconds independent of volume. These are small in the pilot but can accumulate across hundreds of thousands of requests, especially for a faster classifier. The 2%/15% retry assumptions are declared, rather than measurements. Fix: estimate enrichment wall time per new classification from end-to-end stage measurements, separately disclose observed retries and projected retry scenarios; include measured prepare/export overhead and candidate-specific timing.

5. **P2 — Hard process death leaves no terminal accounting or run status.** The request artifact and zero-dollar reservation precede network execution; a kill before `calls` insertion leaves no terminal call row. Run status is inserted only after the entire run completes. Request artifacts are useful forensic evidence, but no startup reconciliation turns them into interrupted/unknown attempts or a failed/interrupted run. A hard kill also leaves a worker lease for up to 900 seconds (`core.py:68-71`). Fix: persist a running run row and attempt state before execution, reconcile orphan attempts on restart, and document safe expired-lease reclamation. Keep unknown paid charges reserved if a paid adapter is ever added.

## Controls that are present

SQLite WAL; transactional label/cache writes; one worker lease per database; database-local shared limiter; exact-text provenance and collision check; one invalid-output retry and at most three transient failures; 600-second HTTP timeout; source hash preservation; cached downstream roles keyed by configuration and stage version; offline default; explicit positive cap strictly below $5; paid routing fails closed. Ledger reservations are always zero because only localhost inference exists; they do not demonstrate a global paid-spend control. Separate databases have separate ledgers and limiters. This is safe for current $0 API execution, but a future paid provider must use an application-wide ledger with real worst-case reservations and settlement.

## Test limitations

Passing tests establish the synthetic schema, same-DB lease collision, budget arithmetic, cached completed-row behavior, stage invalidation helpers, semantic policy, and zero-billed calculator behavior. They do not establish crash-window reconciliation, cross-database spend enforcement, candidate-specific scale gates, model robustness, sustained throughput, or a cloud bill. The planted wrong-label test only compares dictionaries; it is not an independent model verification experiment.

## Scaling recommendation

Do not scale until a candidate-specific completed development benchmark and explicit time projection are available, and the scale command selects that exact profile. Keep human answers held out from prompts and tuning. Existing local-only execution has no API billing route; any new API adapter needs nonzero reservation/settlement and a shared cumulative cap below $5 before it is enabled.

## Remediation implemented in this audit

Preserved the exact pre-change classifier code as `evaluation/frozen/core-at-evaluation.py`; its SHA256 is `a96776ba4d2ec5a075baf96d6312350a587931fa870d363b21a43e63bf1c155b`, matching the original improvement-plan freeze. Prompts, model/schema settings and semantic normalization were not changed.

`pipeline/core.py` now rejects source ID/hash/order conflicts, occupied ordinals and shorter-input replay atomically, while allowing identical replay and an unchanged-prefix extension. It no longer silently ignores a different source record due to ordinal collisions. Separate non-prefix samples require separate databases and an explicit merge.

Successful enrichment attempts now persist their validated output in the call record. Startup recovers successful committed calls that lack labels, validating exact configuration, review ID, input text, output fields/ranges/quote, and direct cache provenance before writing labels/cache in one transaction. Legacy successful call records can be recovered by validating their saved raw response and reapplying only the active frozen policy. Repeated recovery is idempotent; no inference is used.

Attempts now receive an `in_flight` DB row before network execution, runs receive a `running` row, handled interruption records a terminal run/attempt state and releases its lease, and a new lease holder reconciles orphan in-flight attempts/running run rows as interrupted. Expired leases still use the existing 900-second timeout. A response saved only to disk before successful-call DB persistence is still treated as an interrupted request; the recovery guarantee applies to committed successful calls, not unvalidated disk responses. All enabled calls are local and zero-charge.

Validation: **10 new synthetic reliability tests passed**, plus the **18 existing offline controls tests passed**. Tests exercise prefix extension/replay, reordered/different/shorter inputs, atomic rollback, recovery without inference, legacy responses, invalid config/text/IDs/quotes, direct-original provenance, orphan attempt reconciliation, and KeyboardInterrupt terminal run state/lease release. No held-out labels were opened and no inference, scale command, or API charge occurred.

Parent remediation: cost/calculator.py now uses the portable saved cost/checkpoint500_calls.jsonl export instead of requiring an unpublished working DB, and enrichment projections use measured stage time including per-record overhead. cost/portability-check.json records offline replay assertions. The newer faster benchmark has its own stage-specific portable replay and clearly discloses omitted full-corpus preparation/export overhead.

## Hosted deadline revision audit

The user authorized a new hosted GPT-6 Luna partial target of at least 100,000 reviews, with a measured under-$4 admission projection and cumulative API spend strictly below $5. The shared global ledger covers all roles, isolated databases, retries, retained unknown charges and concurrent reservation attempts. An independent follow-up audit found three genuine issues: reservation-overflow usage rollback, treating mere database existence as completed ingestion, and duplicate downstream paid calls after a success/artifact crash window. Parent fixes commit and block on reservation breach, initialize sources atomically and validate count/hash with exactly 100,000 target rows, and recover exact successful verification/memo calls after validating their source/config/prompt identity and outputs. These infrastructure fixes do not alter classifier semantics or human labels.

The actual hosted SIGINT demonstration retained a worst-case $0.003025 reservation for one request whose usage is unavailable. This is disclosed, never fabricated as zero. Standard-library tests include a real overflow reproduction and persistent block assertion. Current paid execution remains guarded by the shared $4.90 cap; final cost and coverage are pending the long run.

The follow-up auditor added 10 synthetic initialization/downstream recovery tests; all passed without touching live state or credentials. The auditor notes that a same-count externally corrupted legacy DB without a manifest could still be adopted without per-row canonical comparison. Current source tables were copied from the previously audited full corpus; no such corruption was observed. Do not treat initialization guards as adversarial tamper detection.
